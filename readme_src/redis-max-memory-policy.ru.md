# Политика вытеснения данных

[English](redis-max-memory-policy.en.md) | **Русский**

В Redis существует **8 основных политик вытеснения данных (eviction policies)**. Они определяют, как именно Redis будет удалять старые ключи, когда объем данных достигнет лимита, указанного в переменной `REDIS_MAXMEMORY`.

Их можно разделить на 3 основные группы в зависимости от алгоритма:

1. **LRU (Least Recently Used)** — удаляет ключи, которые не использовались **дольше всего**.
2. **LFU (Least Frequently Used)** — удаляет ключи, которые используются **реже всего** (по счетчику обращений).
3. **Random / TTL** — случайное удаление или удаление по сроку жизни.

---

Сводная таблица политик (`REDIS_MAXMEMORY_POLICY`)

|Значение переменной|Алгоритм|К каким ключам применяется|Поведение|
|---|---|---|---|
|**`allkeys-lru`** _(Рекомендуется)_|LRU|**Все ключи** без исключения|Удаляет самые старые ключи. Универсальный выбор для обычного кэша.|
|**`volatile-lru`**|LRU|Только ключи с **TTL** (expire)|Удаляет самые старые ключи, но только те, у которых задано время жизни.|
|**`allkeys-lfu`**|LFU|**Все ключи** без исключения|Удаляет ключи с наименьшей частотой запросов.|
|**`volatile-lfu`**|LFU|Только ключи с **TTL** (expire)|Удаляет самые редко используемые ключи среди тех, у которых есть TTL.|
|**`volatile-ttl`**|TTL|Только ключи с **TTL** (expire)|Удаляет ключи, у которых **осталось меньше всего времени жизни** (ближе всего к удалению).|
|**`allkeys-random`**|Random|**Все ключи** без исключения|Просто удаляет случайные ключи, чтобы освободить место.|
|**`volatile-random`**|Random|Только ключи с **TTL** (expire)|Удаляет случайные ключи, но только из тех, у которых есть TTL.|
|**`noeviction`** _(Дефолт)_|—|Ни к каким|**Ничего не удаляет**. При заполнении памяти Redis заблокирует запись и будет возвращать ошибку `OOM command not allowed`.|
